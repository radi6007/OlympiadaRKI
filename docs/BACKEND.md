# Сохранение результатов: Node.js → MySQL → Google Apps Script

## Состав

Все шесть полноценных тестов подключены: RKI-1-V1, RKI-2-V1, RKI-3-V1, RKU-1-V1, RKU-2-V1, RKU-3-V1. Страницы и задания прежние; браузер отправляет JSON только на `POST /api/attempts` своего origin. Node.js 22.12+ и MySQL 8.4+ нужны отдельно от Vite.

`Code.gs` организаторов — источник ключей, проверки ответов, частичных баллов, названий листов и разбивки на части. `server/scoring.js` загружает доверенный локальный файл в изолированный JS-контекст и вызывает оригинальную `grade_` с ограничением времени. Google API из файла в Node не вызываются. Ключи не дублируются в публичных исходниках. Не принимайте этот файл через пользовательский HTTP-запрос.

`.private/Code.gs`, `.env`, данные локальной базы и тестовые отчёты исключены из Git. Vite запрещает выдачу `.private`, `server`, `.env` и `*.gs`. В production публичный корень — **только `dist/`**, не репозиторий. Не копируйте ключи в `public/`, `src/` или переменные `VITE_*`.

## Что хранится

Таблица `olympiad_attempts`, InnoDB, utf8mb4:

- `sid` — глобальный уникальный идентификатор с регистрозависимым сравнением; `test_id`, фамилия, имя, e-mail.
- `answers` — JSON ответов без нормализации: буквы, массивы для two/multi/gap2, объект `{буква: номер}` для match, строки для gap/select.
- `payload` — полный JSON, реально отправленный тестом: `testId`, `sid`, `surname`, `name`, `email`, `answers`, `startedAt`, `finishedAt`, `seconds`, `auto`, `plays`, `lang`, `ua`. Пропуски передаются пустой строкой. Порядок значений массива сохраняется.
- Отдельные UTC-поля начала/завершения, длительность, автозавершение, прослушивания, язык, User-Agent; дата приёма сервером.
- Общий и максимальный балл, массив баллов трёх частей, баллы каждого задания, SHA-256 версии Code.gs, имя листа Google.
- Статус синхронизации `pending/syncing/synced/failed`, число попыток, время последней/следующей попытки, аренда записи работником, последняя ошибка, JSON подтверждения Google, время успеха.

Одно атомарное сохранение InnoDB одновременно сохраняет результат и ставит его в очередь. Ответ API `{ok:true,saved:true,sid,testId}` означает подтверждённую запись MySQL. Он никогда не содержит баллов или ответов. При ошибке базы — HTTP 503, экран ошибки, данные остаются в браузере. Повтор неизменного payload с тем же sid возвращает успех без новой строки; тот же sid с другим содержимым — HTTP 409. На e-mail нет уникального ограничения.

После подтверждения API браузер удаляет персональные данные и ответы, оставляя только `{v:1,phase:'done',serverSaved:true,lang}`. Позднее автосохранение и другая вкладка не восстанавливают удалённые данные. Если очистка браузерного хранилища не удалась, интерфейс сообщает об этом и позволяет повторить запрос/очистку с тем же sid.

`seconds` и времена проверяются на согласованность, но исходный HTML не имеет серверной регистрации начала: это клиентские времена, не доказательство соблюдения лимита. Проверка таймера и числа попыток против намеренного изменения браузера не входит в эту интеграцию.

## Локальный запуск

На текущем Mac установлена отдельная MySQL 8.4.7 в `.tools/mysql/`, база в `.tools/mysql-data/`, TCP `127.0.0.1:3307`. Созданы базы `olympiad` и `olympiad_test`. Настройки уже находятся в локальном `.env`; не перезаписывайте его примером. Пароль локального root лежит в `.private/local-mysql.json`; он не используется API.

```sh
# В корне репозитория. Если Node установлен системно, строка PATH не нужна.
export PATH="$PWD/.tools/node/bin:$PATH"
./scripts/mysql-local.sh start
npm ci
npm run db:migrate
npm run api
```

В другом терминале:

```sh
./scripts/dev.sh --port 5173
```

Открыть `http://127.0.0.1:5173/`. Vite проксирует `/api` на `127.0.0.1:3001`; порт назначения настраивается через `API_PORT`. `GET /api/health` проверяет соединение с MySQL. API не отдаёт списки участников или результаты.

На новой машине:

1. Установить Node.js 22.12+ и MySQL 8.4+, создать базу и отдельного пользователя (пример ниже).
2. Скопировать `.env.example` в `.env`, указать реквизиты MySQL и абсолютный `SCORING_SOURCE_PATH` к приватному Code.gs. Сам Code.gs получить отдельно от организаторов; его нет в Git.
3. Указать опубликованный `APPS_SCRIPT_URL`. Убедиться, что опубликована та же версия Code.gs с шестью идентификаторами. GET проверяет доступность, но не доказывает возможность записи.
4. Выполнить `npm ci`, `npm run db:migrate`, `npm run api`, запустить Vite отдельно.

Только для UI-проверок без отправки: `VITE_RESULTS_MODE=demo npm run dev -- --port 5174 --strictPort`. Демо и рабочий режим используют разные ключи localStorage; старые демопопытки автоматически не отправляются.

## Размещение

Пример SQL от администратора MySQL (пароли заменить):

```sql
CREATE DATABASE olympiad CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER 'olympiad'@'localhost' IDENTIFIED BY 'REPLACE_WITH_SECRET';
GRANT SELECT, INSERT, UPDATE ON olympiad.* TO 'olympiad'@'localhost';
-- Применить server/migrations/001_attempts.sql от администратора
-- либо отдельного пользователя миграций с CREATE/ALTER/INDEX.
```

Заполнить `MYSQL_HOST`, `MYSQL_PORT`, `MYSQL_DATABASE`, `MYSQL_USER`, `MYSQL_PASSWORD`; при удалённой базе — `MYSQL_SSL_CA` для проверяемого TLS. Приватный Code.gs разместить вне web root, дать доступ только пользователю Node. Сохранить резервные копии БД и использованной версии Code.gs; хеш версии хранится в каждой попытке. При изменении ключей нужно согласовать обновление Code.gs и пересчёт обеих систем: автоматический пересчёт ранее сохранённых баллов здесь не выполняется.

Сборка: `npm ci && npm run build`. На сервер поставить `server/`, `src/tests/*/data.js` (схемы без ключей), package.json/lock, production-зависимости (`npm ci --omit=dev`), `.env` и приватный Code.gs. Node запускать постоянно, например systemd:

```ini
[Unit]
Description=Olympiad results API
After=network.target mysql.service

[Service]
User=olympiad
WorkingDirectory=/srv/olympiad
ExecStart=/usr/bin/node --env-file=/srv/olympiad/.env /srv/olympiad/server/index.js
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

Обработчик очереди работает внутри Node API. Не нужен публичный cron/admin endpoint. При рестарте процесса незавершённые записи снова подхватываются после истечения аренды. Для надёжности MySQL оставить `innodb_flush_log_at_trx_commit=1` (по умолчанию), настроить резервные копии и мониторинг failed-записей.

В HTTPS-виртуальном хосте Nginx:

```nginx
root /srv/olympiad/dist;
index index.html;
client_max_body_size 64k;

location /api/ {
    proxy_pass http://127.0.0.1:3001;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 30s;
}
location / {
    try_files $uri $uri/ /index.html;
}
```

API слушает loopback; наружу публикуется только HTTPS-сайт. `.env`, весь репозиторий, Code.gs и MySQL не должны быть публичным web root. Vite dev server и `npm run preview` не используются как production API.

## Очередь и повторная отправка

Работник отправляет **сохранённый payload** серверным POST в Apps Script. Проверяет HTTP, разбирает JSON, требует `ok:true` и совпадение возвращённых баллов с сохранёнными. Google сам формирует столбцы `HEAD_FIXED` и 33 ответа через `cellOf_`. Дата МСК, отметка повторного e-mail и статус письма формируются Google; API скрипта не возвращает их. MySQL хранит все исходные поля и оценки для повторного создания строки, но не выдаёт выдуманный номер строки или статус письма.

При сбое — `failed`, ошибка и время следующей попытки. Автоматический интервал ожидания увеличивается с 30 секунд до 1 часа. Период опроса задаётся `SYNC_INTERVAL_MS`, тайм-аут запроса — `SYNC_TIMEOUT_MS`. Если Google успел записать строку, а ответ потерялся, следующий POST с тем же sid получит `dup:true` без второй строки. SELECT FOR UPDATE SKIP LOCKED и ограниченная по времени аренда позволяют работать нескольким процессам без одновременного захвата записи.

Ручной повтор из терминала сервера:

```sh
npm run sync:retry -- --sid ID_ПОПЫТКИ
# Или по одному разу для всех pending/failed/просроченных syncing:
npm run sync:retry
```

Команда игнорирует задержку backoff, но не захватывает активную аренду и не пересылает synced-записи. Никакие новые sid не создаются. Ошибка Google не отменяет успешное сохранение MySQL и не возвращает участника к форме.

Диагностика без вывода ответов и персональных данных:

```sql
SELECT sid, test_id, sync_status, sync_attempts, sync_last_attempt_at,
       sync_next_attempt_at, sync_error
FROM olympiad_attempts WHERE sync_status <> 'synced';
```

## Проверки

- `node --env-file=.env server/check-all-tests.js --confirm-google-write`: сквозная проверка **всех шести тестов через обычный работающий сайт/API** (по умолчанию `http://127.0.0.1:5173`, другой адрес — `CHECK_BASE_URL`). Создаёт по одной настоящей строке в каждом листе Google с фамилией `__ТЕСТ_ВСЕХ_НАПРАВЛЕНИЙ__`, именем `НЕ УЧАСТНИК <testId>` и e-mail `olympiad-all-tests@example.invalid`. Обычный API и его работник должны работать. Проверяются все 33 задания, исходный payload, оценки, аудио, восстановление, благодарность, очистка localStorage и автоматическая синхронизация. Затем серверный повтор проверяет `dup:true` без новой строки. Отчёт с sid сохраняется в `test-results/all-tests-live-report.json`. Может вызвать письма организатору; не запускать автоматически в CI.
- `npm test`: 21 проверка в изолированном деморежиме, без обращения к Google.
- `npm run test:server`: 6 MySQL-интеграционных и браузерных проверок рабочего режима. Нужна отдельная БД `olympiad_test` (или TEST_MYSQL_DATABASE с суффиксом `_test`) с правами CREATE/SELECT/INSERT/UPDATE/DELETE. Тест сам запускает временный Vite на 5192. Используется локальная имитация Google, реальные письма/строки не создаются. Созданные тестом строки удаляются. Приватный Code.gs нужен для проверки оценки, ключи не содержатся в тестовых файлах.
- `node --env-file=.env server/live-check.js --confirm-google-write`: **создаёт две явно помеченные строки в настоящей Google-таблице** и может вызвать уведомления организатору из Code.gs. Запускать вручную, остановив обычный процесс API, чтобы его работник не вмешивался в проверку сбоя. Тест использует MySQL из `.env`, отдельные API/Vite на loopback (Vite 5191), проходит интерфейс и затем проверяет синхронизацию и повтор по sid. Отчёт — `test-results/live-report.json`. Эти две строки автоматически не удаляются.
