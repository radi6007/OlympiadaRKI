# «Русский язык: код единства» — локальный прототип

Vite, JavaScript, CSS. Главная и шесть страниц направлений используют тексты RU/EN из HTML-макета. Все шесть направлений имеют отдельные HTML-точки входа с полными тестами. Все шрифты, изображения и аудио локальные.

Сохранение результатов подключено через Node.js → MySQL → Google Apps Script. Для рабочего режима дополнительно запустить базу и API по [инструкции сервера](docs/BACKEND.md); одного Vite недостаточно.

## Запуск

```sh
cd /Users/andreyshepelev/OlympiadaRKI/OlympiadaRKI
./scripts/dev.sh
```

Открыть http://127.0.0.1:5173. Скрипт использует Node из PATH или локальную копию `.tools/node` (подготовлена на этом компьютере, исключена из Git). Если зависимостей нет, выполнит `npm ci`.

Для нового компьютера нужен Node.js 22.12+ и npm:

```sh
npm ci
npm run dev
```

Стандартные команды на текущем компьютере, где Node отсутствовал в PATH:

```sh
export PATH="$PWD/.tools/node/bin:$PATH"
npm run build
npm run preview
npx playwright install chromium
npm test
```

`npm run preview` обслуживает сборку на http://127.0.0.1:4173. Для проверки на телефоне в одной сети: `./scripts/dev.sh --host 0.0.0.0`, затем открыть LAN-адрес компьютера с портом 5173. Прогресс привязан к браузеру и origin; между localhost, IP, портами и устройствами он не переносится.

## Сохранение результатов и деморежим

В рабочем режиме (`VITE_RESULTS_MODE=api`) все шесть тестов отправляют результат на собственный Node API. Он сохраняет исходные ответы, данные участника, серверные баллы и очередь в MySQL. Только после этого появляется благодарность и очищаются данные в браузере. Сбой Google не отменяет успешное сохранение MySQL. Баллы участнику не показываются.

Настройки, миграция, локальный запуск MySQL/API, размещение и ручной повтор описаны в [docs/BACKEND.md](docs/BACKEND.md). Ключи находятся в приватном Code.gs вне Git и публичной сборки. Для полноценного запуска нужны и MySQL, и `npm run api`, и Vite.

Для UI-проверки без отправки явно установить `VITE_RESULTS_MODE=demo`. Рабочие и демопопытки используют разные ключи localStorage. Демотест можно пройти заново кнопкой на экране благодарности; рабочий тест такой кнопки не имеет. E-mail не уникален.

Таймер отсчитывает 90 минут по абсолютному времени. РКУ-1 и РКУ-2 допускают одно прослушивание, остальные — два. В пяти новых тестах аудиоотсчёт продолжается при перезагрузке, как в исходниках; РКИ-1 сохраняет прежнее восстановление позиции.

## Подключённые тесты и расширение

Добавлены РКИ-2, РКИ-3, РКУ-1, РКУ-2 и РКУ-3 из одноимённых HTML. Файл «Олимпиада_РКИ-1_тест (1).html» содержит те же задания, части и аудио, что уже подключённый РКИ-1; отличается настройками и реализацией интерфейса. Дублирующая попытка не создана, существующий РКИ-1 и его прогресс сохранены.

Общий движок `src/tests/engine.js` поддерживает один ответ, два ответа, несколько ответов, сопоставление, текстовые пропуски и выпадающий список. В `src/tests/<slug>/data.js` сохранён исходный блок данных; соседний `engine.js` запускает общий движок с конфигурацией направления. `source-copy.js` содержит интерфейсные тексты новых исходников. Хранение разделено по `TEST.id`. Контрольные суммы данных и аудио проверяются для всех шести тестов.

Для следующего теста:

1. Получить и проверить соответствующий HTML: задания, варианты, аудио, длительность, ограничения, языки. Не заменять его заданиями РКИ-1.
2. Создать отдельную точку входа `<slug>/test/index.html` и модуль `src/tests/<slug>/`. РКИ-2 служит примером разделения на `data.js` и `engine.js`, использующий общий движок. Данные и поведение будущего HTML могут отличаться — адаптировать их после изучения.
3. Подключить общие `src/fonts.css`, `src/design-tokens.css`, `src/tests/test.css`, `src/tests/shared.css` и демотексты `src/tests/demo.js`. Для иконок использовать `src/icons.js`. Скопировать CSP из существующей точки входа, удалить любые внешние обработчики отправки. Для хранения использовать уникальный ID теста.
4. Добавить HTML в `build.rollupOptions.input` в `vite.config.js`.
5. В `src/content.json` добавить `STREAMS[].testPath` со значением `/<slug>/test/`. Тогда страница автоматически покажет согласие с правилами и кнопку начала. До готовности нового теста оставить `null`.
6. Прогнать сценарий от ввода данных до завершения, восстановление, таймер и аудио. Добавить проверку новой точки входа в браузерные тесты.

`src/content.json` — единый реестр направлений и текстов. `src/app.js` — страницы и переходы. `src/design-tokens.css` — общие цвета, шрифт, ширина и скругления. `src/layout.css` — базовая сетка; `src/product.css` — компоненты информационных страниц. `src/icons.js` — заполненные SVG-иконки. `src/tests/shared.css` — оформление теста и благодарности. Содержимое блоков данных всех шести тестов и MP3 сохранено побайтно; контрольные SHA-256 проверяются в тестах.
